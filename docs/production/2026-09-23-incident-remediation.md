## Diagnostics prepared for a recurrence

The local source now records the WhatsApp template name and language used by a failed Cloud test or exam-result send, alongside Meta's status and error code. This logs no recipient, template parameters, access token, or message body. For 132001, compare that exact pair with the approved templates in the connected business account before changing configuration or resending.

After a Redis Sentinel outage lasts 15 seconds, each worker will make one bounded TCP connection attempt to every configured Sentinel and log only the endpoint index and the result. The event also records worker node, Redis connection status, and Sentinel count. A reachable TCP port does not prove Sentinel protocol health or quorum; correlate the timestamp with retained Sentinel journals and network events. The probe does not authenticate or issue Redis commands.

Bunny HLS client error events now include capped elapsed loading time, browser online state, and visible/hidden state. These are recorded with the existing session and lesson correlation fields, without signed media URLs, IP addresses, or browser network payloads. They distinguish a browser that reports offline or backgrounded from a visible online timeout, but CDN edge and origin traces are still needed to attribute the latter. The gateway now emits a separate 5xx-only record with request ID, path without query, upstream status, and connection/header/response durations. Its existing container log rotation still limits retrospective coverage; collect a bounded copy promptly after a recurrence.

These diagnostics are source changes only. They cannot explain the earlier events retroactively and will not appear in production until a separately authorized release passes its gates.
