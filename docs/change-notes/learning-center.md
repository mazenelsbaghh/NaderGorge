# مركز التقييم والمتابعة

الحالة: تنفيذ محلي فقط. طلب المالك صراحة عدم الرفع إلى السيرفر.
نطاق التحقق والبناء الذي وافق عليه المالك: `all`.
المكونات المتغيرة: الواجهة، الباك إند، وقاعدة البيانات. لم يتغير كود worker.

## الوصول

- الأدمن: `/admin/learning-center`، متاح لدور Admin فقط.
- المدرّس: `/teacher/learning-center`، مقتصر على بيانات مدرّسه. عضو فريق المدرّس يحتاج صلاحيتي `content` و`students` معًا.
- API مشتركة تحت `/api/learning-center`، مع إعادة فحص الدور ونطاق الملكية في طبقة التطبيق.
- شاشات الأسئلة والامتحانات السابقة تظل موجودة.

## السلوك المنفذ

### خريطة الفهم

تصفية بالكورس، المدرّس، المادة، الصف، والفترة. تُربط أسئلة الامتحانات بدرس وفكرة وصعوبة متوقعة. تظهر أعداد الطلاب والمحاولات، أكثر الاختيارات الخاطئة، الطلاب الأقل من 60% في الفكرة، والتطور اليومي بتوقيت القاهرة.

نسبة الفهم تستخدم آخر إجابة لكل طالب على كل سؤال. أقل من خمسة طلاب يظهر كعينة غير كافية؛ تكرار محاولة الطالب لا يرفع عدد الطلاب. تُستبعد المحاولات المفتوحة، المقاليات غير المصححة نهائيًا، والمراجعات التي تتطلب استكمالًا أو مراجعة، والنتائج خارج نطاق الدرجة الكلية.

مؤشر فرق أداء المستويات يقارن الثلث الأعلى والأقل في نتائج الامتحان، عند وجود عشرة طلاب على الأقل. هو مؤشر مراجعة، وليس إثباتًا لتكافؤ صعوبة الامتحانات. تصنيف السؤال الحالي ينظم النتائج التاريخية أيضًا.

### المتابعة

القائمة مبنية على الاشتراكات السارية للكورسات. آخر نشاط يُجمع من مشاهدة الفيديو المقبولة، وبدء الامتحانات، وبدء أو تسليم الواجبات. انخفاض النتيجة وتكرار المحاولات يُقاسان على نفس الامتحان ونفس تعريفه المحفوظ، ولا تُستخدم المحاولات القديمة دون نسخة محفوظة لإثبات انخفاض قابل للمقارنة.

حدود التنبيه قابلة للتعديل ضمن فلاتر الصفحة: أيام التوقف، مقدار الانخفاض، وعدد المحاولات. تُحفظ الحالة والملاحظة والسبب وصاحب التعديل في سجل إضافات متتابع. الحالات: جديد، جارٍ المتابعة، تمت المتابعة. إتمام المتابعة لا يخفي سببًا ما زال نشطًا. سجل الواجهة يعرض آخر 100 إدخال، والأقدم يظل محفوظًا.

التحسن بعد المتابعة يظهر فقط عند وجود نتيجة قبلها وأخرى بعدها لنفس نسخة الامتحان ضمن الفترة المختارة. تسجيل الملاحظة لا يرسل رسالة أو إشعارًا للطالب.

### بنك الأسئلة والنماذج

- بحث وتصفية بالمدرّس والمادة والكورس والدرس والصعوبة؛ تشمل النتائج الأسئلة القديمة التي تحتاج تصنيفًا.
- إنشاء أسئلة اختيار من متعدد يدويًا، أو استيراد ملف JSON بالقالب بعد اختيار الدرس. الاستيراد محدود بـ100 سؤال و2 ميجابايت في الواجهة، والحفظ على قاعدة البيانات يتم داخل معاملة واحدة.
- يمكن تصنيف الأنواع الموجودة مسبقًا. تعديل نص سؤال MCQ ينشئ نسخة جديدة؛ روابط الامتحانات السابقة ونسخ محاولاتها تبقى على السؤال الأصلي.
- توليد 1–5 نماذج، بحد أقصى 100 سؤال للنموذج. نفس توزيع الدرس والفكرة والصعوبة والدرجات، بأسئلة مختلفة بين النماذج.
- نقص الأسئلة بالدرجات المطلوبة يرفض إنشاء المجموعة كاملة. النماذج تُحفظ غير مفعّلة للمراجعة والربط بالمحتوى من شاشات الامتحانات القائمة.
- إعادة طلب توليد المجموعة بنفس معرف الطلب والمواصفات تعيد نفس الامتحانات. تغيّر المواصفات مع نفس المعرف يُرفض.
- الإنشاء والتصنيف وإصدار النسخ والمتابعة والتوليد مسجلة في سجل التدقيق.

## قاعدة البيانات وحدود القراءة

Migration: `20260912162654_AddLearningCenter`، مع ملف Designer وتحديث ModelSnapshot.
تضيف تصنيف الأسئلة وربطها بالدروس ومرجع النسخة البديلة، وجدول `learning_follow_ups`.
طبقت واختبرت على PostgreSQL 16 محلية معزولة؛ لم تُطبّق على السيرفر.

قراءة التحليل ترفض نطاقًا يتجاوز 5000 محاولة أو 50000 إجابة، وتطلب فترة أو كورسًا أضيق. المتابعة ترفض أكثر من 10000 ارتباط طالب بكورس. لا يُعرض جزء من النتائج على أنه النتيجة الكاملة.

## التحقق

- اختبارات التطبيق: 1320 ناجحة، واختبارا Redis متخطّيان بسبب متطلبات البيئة القائمة.
- اختبارات PostgreSQL الخاصة بالميزة: 7 سيناريوهات تشمل العزل، حفظ النسخ، العينة والتكرار، النماذج وإعادة الطلب، المتابعة، والتراجع الكامل عن استيراد فاشل.
- بناء Next.js النهائي والفحص النوعي نجحا. lint بلا أخطاء؛ يوجد تحذير سابق في `ChatContainer.tsx`.
- `make ops-db-guard OPS_BASE=HEAD` نجح قبل ظهور تعديلات متزامنة أخرى في الدعم المباشر. إعادة الفحص المشترك توقفت لاحقًا عند `LiveSupportBlockPolicy.cs` من تلك التعديلات. تم التحقق مجددًا من كود الميزة وحده في نسخة محلية معزولة: البناء واختبارات PostgreSQL السبعة نجحت، و`has-pending-model-changes` أكد تغطية النموذج بالـmigration. لم تُعدّل ملفات العمل الآخر.
- `make verify`: نجح بناء الباك إند والواجهة وworker واختبارات التطبيق، ثم توقف لأن `AI_MEDIA_RELAY_SECRET` غير مضبوط في البيئة المحلية الافتراضية. فحص Compose نجح بإعطائه قيمة اختبار محلية دون تشغيل أو نشر أي خدمة إنتاج.
- اختبار المتصفح استخدم API محلية حقيقية وقاعدة الاختبار، وليس استجابات محاكاة. صور المراجعة محفوظة في `artifacts/learning-center/`.
- ملفات حصر endpoints وروابط الواجهة وقدرات Admin AI أُعيد توليدها. فحص الحصر يكشف ثلاثة استدعاءات قديمة في `assessment-revision-service.ts` لا يحل المحلل الساكن دالة مسارها؛ 13 من 15 اختبار حصر نجحت. لم تُخفَ هذه النتائج أو تُعطّل الاختبارات.
- اختبارات عقود الأداء: 26 ناجحة. بوابة قياسات الأداء ترفض القياسات السابقة لأن المصدر تغير بعدها؛ لم تُنشأ أرقام أداء بديلة أو يُدّعَ اجتياز هذه البوابة.

## إعادة تشغيل الاختبارات المحلية

تحتاج صورة `postgres:16-alpine` متاحة محليًا. قاعدة الاختبار مخصصة لهذه الميزة، وليست قاعدة التطوير أو الإنتاج:

```bash
docker run --pull=never --name massar-learning-center-test \
  -e POSTGRES_PASSWORD=learning-test-only -e POSTGRES_DB=massar_learning_test \
  -p 127.0.0.1:55441:5432 -d postgres:16-alpine

dotnet test backend/tests/NaderGorge.Integration.Tests/NaderGorge.Integration.Tests.csproj \
  --filter FullyQualifiedName~LearningCenterTests
```

يمكن تخصيص اتصال الاختبار عبر `MASSAR_LEARNING_TEST_CONNECTION`؛ fixture يرفض أي مضيف غير محلي أو اسم قاعدة مختلف عن `massar_learning_test`.
