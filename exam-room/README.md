# مسار · امتحانات السنتر — نسخة تجربة محلية

تطبيق مستقل بهوية مسار. الكمبيوتر يستضيف الامتحان ويحفظ البيانات، والطلاب يفتحونه من متصفح الموبايل على نفس الشبكة. التشغيل والامتحان لا يحتاجان إنترنت، ولا يستخدم التطبيق حسابات أو قواعد بيانات منصة مسار.

البرنامج له باك إند محلي مكتوب بـGo يحفظ البيانات في SQLite على نفس الكمبيوتر. واجهة الإدارة داخل البرنامج مكتوبة بـReact وتُبنى كملفات ثابتة مضمّنة في خادم Go؛ صفحة الطالب خفيفة بـHTML وCSS وJavaScript. تستخدم حزمة سطح المكتب Python وpywebview لفتح النافذة وتشغيل الخادم، وحفظ التنزيلات وتهيئة الشبكة وفحصها. لا يوجد خادم سحابي للامتحان؛ تصحيح Gemini وخدمات الرسائل وإصدار شهادة البوابة وتجديدها تحتاج إنترنت، بينما الحل والحفظ يعملان محليًا. ملفات Python داخل `room/` محفوظة كمرجع للنسخة السابقة؛ التشغيل الحالي يستخدم خادم Go فقط.

## التشغيل كبرنامج مستقل

مثبّت macOS للنسخة الجديدة هو `dist/Massar-Exam-Room-macOS-arm64-Installer.pkg`. افتحه واتبع خطوات التثبيت؛ سيضع `Massar Exam Room.app` في مجلد Applications. لا تحتاج تثبيت Python أو Go على الجهاز الذي سيستخدم البرنامج. توجد أيضًا نسخة ZIP محمولة في `dist/Massar-Exam-Room-macOS-arm64-Go.zip`. نافذة الإدارة وخادم الطلاب يعملان معًا، وإغلاق البرنامج يوقف اتصال الطلاب بعد تنبيه تأكيد. اتركه مفتوحًا طوال الامتحان. إذا كانت نسخة أقدم مفتوحة، أنهِ الجلسة وأغلقها أولًا ثم افتح الحزمة الجديدة؛ تظل قاعدة البيانات في مجلدها الثابت.

النسخة مبنية على جهاز Apple Silicon ومجرّبة على macOS 26.3. لم نختبرها على Intel أو إصدارات macOS أقدم. التطبيق داخل الحزمة موقّع محليًا، لكن ملف `.pkg` غير موقّع بشهادة Developer ID Installer ولم يخضع لتوثيق Apple notarization. قد يمنع macOS فتحه مباشرة؛ افتحه من قائمة زر الماوس الأيمن ← «فتح»، أو اسمح به من إعدادات الخصوصية والأمان بعد محاولة الفتح. للتوزيع العام السلس يلزم توقيع Apple وتوثيق الحزمة.

في Windows توجد أداة بناء `Build-Windows.bat`، **ولا يوجد مثبّت Windows مبني أو مجرّب في هذه البيئة**. تُشغّل الأداة على Windows مع Python 3.10+ وGo 1.27.1 أو أحدث وNode.js/npm وInno Setup 6 واتصال إنترنت لتنزيل حزم البناء. الناتج `dist/Massar-Exam-Room-Windows-Setup.exe`، وهو مثبّت يضع التطبيق في Program Files ويضيف اختصارًا. التشغيل الناتج يحتاج Microsoft Edge WebView2 Runtime. البناء على كل نظام مستقل، حسب [توثيق PyInstaller](https://www.pyinstaller.org/en/stable/). اعتمد نسخة Windows بعد اختبارها على الجهاز المستهدف.

لبناء نسخة macOS من المصدر يلزم Go وNode.js/npm وPython وحزم سطح المكتب:

```sh
python3 -m venv .build-env
.build-env/bin/python -m pip install -r requirements-desktop.txt
.build-env/bin/python build_desktop.py
```

## التشغيل من المصدر في المتصفح

هذا البديل يحتاج Python 3.10+ وGo 1.27.1 أو أحدث لبناء وتشغيل الخادم: `Start-Massar.command` على macOS أو `Start-Massar.bat` على Windows. أبقِ نافذة التشغيل مفتوحة. أو شغّل من مجلد التطبيق:

```sh
python3 run.py
```

على Windows استخدم `py -3 run.py`. يُبنى خادم Go محليًا عند تشغيل المصدر. لوحة الإدارة `http://127.0.0.1:8766`؛ الطلاب على منفذ 8765. لا تشغّل البرنامج ونسخة المصدر معًا على نفس المنافذ. البيانات المفتوحة في عملية أخرى محمية بقفل نظام التشغيل؛ عند رسالة التعارض أغلق النسخة الأخرى وأعد المحاولة.

## أول تجربة

1. وصّل الكمبيوتر والهواتف بنفس الراوتر، ويفضل كابل شبكة للكمبيوتر. يمكن فصل الإنترنت عن الراوتر مع بقاء الشبكة المحلية تعمل.
2. اسمح لاتصالات برنامج مسار الواردة (أو خادم Go عند التشغيل من المصدر) على الشبكة الخاصة إذا طلب جدار الحماية ذلك. لا تفتح المنفذ على الإنترنت. يجب أن يسمح إعداد الشبكة للهواتف بالوصول إلى الكمبيوتر؛ شبكة الضيوف المعزولة قد تمنع ذلك.
3. اضغط «ابدأ بامتحان تجريبي»: أربعة أسئلة جاهزة. أو أنشئ أسئلتك من «إنشاء امتحان».
4. افتح قاعة الانتظار؛ لا تحتاج توليد أو توزيع أكواد للامتحان. افتح على الموبايل **رابط الطلاب الظاهر في اللوحة** أو امسح QR. عنوان `127.0.0.1` يخص الكمبيوتر نفسه ولا يصلح على هاتف الطالب.
5. الطالب يكتب اسمه ورقمه وكوده الحالي في السنتر، وينتظر. البيانات تُقبل كما كتبها الطالب بدون مراجعة كشف مسبق؛ الكود ليس كلمة سر أو كود شراء. يُمنع تكرار نفس الكود في نفس الامتحان، ويُسمح باستخدامه في امتحانات أخرى. اضغط «ابدأ الامتحان للجميع» لبدء الوقت وظهور الأسئلة تلقائيًا خلال دورة التحديث، عادة نحو ثلاث ثوانٍ.
6. افتح «الإعدادات والبيانات» وأدخل مفتاح Gemini API في قسم «إعدادات التصحيح» مرة واحدة. بعد إنهاء الامتحان، افتح «التصحيح والنتائج» واضغط «تصحيح المقالي للجميع» وانتظر اكتمال العداد. راجع الإجابات التي تحتاج تدخلًا، ويمكنك تعديل أي درجة يدويًا. عند اكتمال التصحيح افتح «تقرير التصحيح / PDF»، ثم اختر الحفظ كـPDF من نافذة الطباعة.

ابدأ بعدد قليل من الهواتف ثم زوّد العدد. اختبار ١٠٠ جلسة على الكمبيوتر لا يثبت قدرة الراوتر على خدمة ١٠٠ موبايل فعلي.

## الموجود في النسخة

- أسئلة اختيارات ومقالي مكتوب، درجات وإجابات نموذجية، ترتيب عشوائي واختيار عدد من بنك الأسئلة.
- عند اختيار عينة من البنك، يجب أن تكون درجات الأسئلة متساوية حتى يتساوى المجموع بين الطلاب.
- نهاية موحدة للجميع، أو مدة كاملة للطالب المتأخر؛ الطلاب الموجودون في الانتظار يبدأ وقتهم عند بدء المدرس. يمكن منع الدخول المتأخر.
- تسجيل بكود الطالب الحالي، حضور، حفظ تلقائي للإجابات، استعادة الدخول، تسليم يدوي أو عند انتهاء الوقت.
- سؤال واحد ظاهر في كل خطوة مع السابق والتالي وأرقام للتنقل. الإجابات والخطوة الحالية تبقيان بعد إعادة تحميل الصفحة، والتسليم متاح من الخطوة الأخيرة.
- لا تُرسل الإجابات النموذجية أو الدرجات إلى واجهة الطالب؛ بعد التسليم يرى تأكيد الاستلام فقط.
- تصحيح MCQ تلقائي، وتصحيح مقالي جماعي عبر Gemini بعد انتهاء الامتحان، مع إمكانية المراجعة والتعديل اليدوي، وتقارير قابلة للطباعة، وتصدير CSV.
- مكتبة امتحانات قابلة للبحث والتصفية، وفلاتر حضور وتسليم وتصحيح، وتنبيه قبل مغادرة تعديل غير محفوظ.
- شاشة «الإعدادات والبيانات» تعرض المسار الفعلي والحجم والمساحة المتاحة والعدادات، وتفتح المجلد وتفحص بنية SQLite وتُنشئ وتُنزل النسخ.
- قاعدة SQLite مستقلة ونسخ احتياطية محلية. خادم Go يقرأ قاعدة النسخة الحالية ويحافظ على المحاولات والإجابات، ويرقّي مخطط SQLite رقم 1 إلى رقم 2 تلقائيًا بعد إنشاء نسخة احتياطية.

التصحيح الجماعي يحتاج إنترنت على جهاز الإدارة فقط. يرسل نص السؤال والإجابة النموذجية وإجابة الطالب إلى Gemini، بدون اسم الطالب أو هاتفه؛ يستخدم `gemini-3.5-flash-lite`، مع خيار صح أو غلط أو درجات جزئية بخطوات نصف درجة. يرسل حتى خمسة طلبات معًا، وينتظر خمس ثوانٍ بعد انتهاء الدفعة قبل التالية. في الإصدار 0.4.8 يطلب درجة نهائية لكل إجابة، حسب المعنى والأجزاء الصحيحة المفهومة، دون إرجاع الإجابات للمراجعة. الأجزاء غير المفهومة لا تُمنح نقاطًا. خطأ الاتصال أو النتيجة غير الصالحة يبقيان الإجابة بدون درجة؛ يمكن إعادة تصحيحها بعد إصلاح السبب أو تعديلها يدويًا. إعادة تشغيل التصحيح تشمل الإجابات التي ما زالت بدون درجة وتحافظ على الدرجات المحفوظة. يُحفظ المفتاح نصيًا في ملف `.env` داخل مجلد بيانات البرنامج، وليس داخل SQLite أو حزمة التطبيق أو ملفات النسخ الاحتياطية؛ الملف مخصص لحساب مستخدم الكمبيوتر فقط ولا يُنشر في المصدر. لا تشارك ملف `.env` لأنه يحتوي المفتاح. إذا كان المفتاح في Keychain من نسخة قديمة فقط، أدخله مجددًا من شاشة الإعدادات ليُحفظ في `.env`. قد تنطبق حدود الاستخدام وتكاليف حساب Google؛ توقف الشبكة أو انتهاء الحصة يترك ما صُحح محفوظًا، ويمكن إعادة تشغيل الباقي. راجع أحكام Gemini قبل اعتماد النتائج النهائية.

**حدود التشغيل:** إعداد شبكة الماك المباشرة متاح من البرنامج، لكن إعدادات ترددات وقنوات وحماية Omada تُضبط من صفحة الجهاز. ظهور نافذة الدخول تلقائيًا يعتمد على نظام الهاتف؛ رابط HTTP وQR بديلان. النظام لا يفتح متصفح هاتف عن بُعد، ولا يفصل الهاتف من الواي فاي بزر، ولا يمنع استخدام بيانات الموبايل أو تطبيقات أخرى. إرسال Meta WhatsApp وتنزيل PDF وZIP متاحان كما في قسم واتساب وتقارير الطلاب أدناه.

### بوابة Omada EAP620 HD المحلية (إعداد اختياري)

الـEAP620 HD في وضعه المستقل يوفّر `Wireless > Portal > No Authentication`، لكن خانة `The Promotional URL` في إصدار البرنامج الثابت المجرب لا تقبل المنفذ `:8765`. على الماك يمكن بناء وتثبيت `install-macos-portal.sh` من هذا المجلد؛ يفتح خدمة الطلاب فقط على منفذ HTTP الافتراضي 80 ويحيلها إلى `127.0.0.1:8765`. لا يفتح لوحة الإدارة على 8766. سيطلب `sudo` كلمة مرور macOS من صاحب الجهاز في Terminal. للإزالة استخدم `uninstall-macos-portal.sh`.

يمكن الاستغناء عن الراوتر نهائيًا في شبكة الامتحان: `Mac Ethernet → EAP620 HD → هواتف الطلاب`. إذا كان الأكسس بوينت يتغذّى من محوّل 12V/1.5A مستقل، وصّل كابل الشبكة مباشرةً. في هذا التوصيل يصبح الماك مسؤولًا عن إعطاء عناوين IP للطلاب عبر خدمة DHCP محلية، مع عنوان ثابت لنفسه وللأكسس بوينت. لا يكفي توصيل الكابل وحده؛ الـEAP في وضع Access Point لا يؤدي وظيفة DHCP التي يؤديها الراوتر عادةً.

في نسخة الماك 0.2.6، افتح «الإعدادات والبيانات» ← «تهيئة الاتصال المباشر بالـOmada» واضغط «تهيئة الماك الآن». يطلب macOS كلمة سر الجهاز في نافذته المعتادة؛ التطبيق لا يستقبلها. يجهّز عنوان الماك `10.77.0.1/22`، ويحجز `10.77.0.2` للأكسس بوينت، ويوزّع العناوين `10.77.0.20` حتى `10.77.3.250`، ويثبّت وصلة منفذ 80 المذكورة أعلاه. يكتشف منفذ Ethernet الموجود على الجهاز، بما فيه محوّلات USB، ولا يحتاج إنترنت يوم الامتحان. يتضمن المثبّت خدمة توزيع العناوين ولا يحتاج تثبيت Homebrew على ماك الامتحان. إذا توقفت الخدمة، يعرض البرنامج سبب التوقف من سجلها المحلي. شيفرة المصدر ورخصة dnsmasq 2.93 داخل التطبيق في `Contents/Resources/third-party/`. يظل `install-macos-direct-network.sh` بديلًا من المصدر، وللإزالة واستعادة إعداد Ethernet السابق القائم على DHCP استخدم `uninstall-macos-direct-network.sh`. هذا الإعداد لم يُشغّل أو يُختبر بعد على الأجهزة الفعلية؛ اختبره بهواتف حقيقية وابدأ بعدد صغير قبل الاعتماد عليه مع 500 طالب.

بعد تشغيل DHCP وربط الأجهزة، اختبر `http://10.77.0.1/` من هاتف على شبكة الامتحان أولًا. النسخة 0.2.6 توجّه فحوص الاتصال عبر HTTP إلى صفحة الطلاب المحلية، كي يستطيع الهاتف إظهار نافذة الدخول. لا تفعّل بوابة الـOmada الداخلية إذا أردت صفحة الامتحان مباشرة؛ بوابة No Authentication تعرض صفحة موافقة وزر دخول قبل التحويل. ظهور نافذة الدخول تلقائيًا يعتمد على نظام الهاتف ولا يمكن ضمانه لكل الأجهزة، لذا احتفظ برمز QR أو رابط الامتحان كبديل.

على Windows يمكن تشغيل خادم الطلاب مباشرة على المنفذ 80 (`--port 80`) بعد التأكد أنه غير مستخدم، وإضافة سماح وارد لشبكة الامتحان الخاصة فقط. يحتاج ذلك بناء حزمة Windows واختبارها على الجهاز المستهدف؛ لم يتم التحقق من Windows هنا. احفظ عنوان الكمبيوتر ثابتًا في الراوتر واستخدم `http://<عنوان الكمبيوتر>/` عنوان تحويل البوابة.

### شهادة الدخول المعياري في macOS (0.4.19)

من الإصدار 0.4.20، افتح «تهيئة الاتصال المباشر بالـOmada» ← «طريقة دخول الطلاب»، واختر:

- «دخول محلي بدون شهادة»: الطريقة القديمة بعنوان `http://10.77.0.1/` مع فحوص الدخول التقليدية. لا تحتاج شهادة أو تجديدًا. تعطّل التهيئة إعلان CAPPORT ومستمع HTTPS، وتحتفظ بملفات الشهادة لإعادة استخدامها لاحقًا؛ لا تمنعها شهادة محفوظة منتهية.
- «دخول آمن بشهادة»: تضيف HTTPS والاكتشاف المعياري للأجهزة الداعمة، وتحتاج شهادة موثوقة صالحة.

حفظ الاختيار وحده لا يغيّر الشبكة. الشاشة تميّز بين الاختيار المحفوظ والوضع المطبّق، ويُعرض HTTPS في الرابط وQR عندما يكون مطبّقًا ويفحصه البرنامج بنجاح؛ عند تعذّر التحقق أو انتهاء الشهادة يُعرض الرابط المحلي بديلًا قبل تسجيل الدخول. من بدأ المحاولة يستمر على نفس رابطه ومتصفحه. بعد إغلاق القاعات اضغط «تحديث تجهيز الماك» لتطبيق التغيير. عند الفشل يحتفظ البرنامج بالاختيار لإعادة المحاولة، ويحاول المثبّت استعادة الوضع السابق. لا يتحول HTTPS تلقائيًا إلى الوضع المحلي عند انتهاء الشهادة.

عند اختيار الدخول الآمن، أدخل عنوانًا تملكه، مثل `exam.massar-academy.net`. اضغط «اختيار شهادة البوابة وتجديدها»، واختر `fullchain.pem` ثم `privkey.pem` المطابق. يفحص البرنامج اسم النطاق والصلاحية وسلسلة الثقة قبل حفظ الاختيار. شهادة Cloudflare Origin وحدها لا تكفي؛ يلزم شهادة موثوقة لدى الهواتف. يظل المفتاح محليًا خارج حزمة التطبيق، ولا تشاركه مع الطلاب.

بعد انتهاء الطلاب وإغلاق القاعات، اضغط «تحديث تجهيز الماك». يطلب macOS كلمة سر الجهاز لتطبيق الإعداد. لا يعلن التطبيق بوابة HTTPS في الشبكة قبل اجتياز فحص الشهادة. عند تفعيلها، يعلن DHCP خيار 114 بعنوان `https://<النطاق>/capport` وتعمل صفحة الطالب وواجهاتها على HTTPS. يظل رابط HTTP المحلي بديلًا قبل تسجيل الدخول؛ استمر على نفس الرابط والمتصفح بعد بدء المحاولة. قد يحتاج الهاتف نسيان شبكة الامتحان وإعادة الاتصال ليحصل على إعداد DHCP الجديد.

DNS الخاص بشبكة الامتحان يوجّه اسم النطاق إلى `10.77.0.1` محليًا؛ لا يحتاج تغيير عنوان الموقع العام أو نشر عنوان الماك على الإنترنت. لا يؤثر تغير عنوان Wi-Fi أو الإنترنت على عنوان Ethernet الثابت المخصص للامتحان. إصدار الشهادة عبر DNS-01 يحتاج إنترنت وإضافة سجل TXT لإثبات ملكية الدومين، لكن الطلبات أثناء الامتحان تصل إلى الماك عبر الشبكة المحلية. راجع [شرح DNS-01 الرسمي](https://letsencrypt.org/docs/challenge-types/).

الشهادة التي تصدر بالتحقق اليدوي لا تتجدد تلقائيًا. يعرض البرنامج تحذيرًا حين يتبقى أقل من 21 يومًا؛ أعد إصدارها ثم اختر الملفين الجديدين وطبّق التحديث قبل الامتحان. لا تُحذف إعدادات الشهادة الحالية عند تحديث الشبكة دون اختيار بديل. يحاول المثبّت استعادة إعداد الخدمات والشبكة السابق إذا فشلت عملية التحديث، ويبلغك إذا لم تكتمل الاستعادة. مدة حجز عنوان DHCP أصبحت ساعة؛ الأجهزة المتصلة تجدد الحجز، وتظهر سعة العناوين ومشكلات قراءتها في فحص الاتصال.

فحص البوابة يتحقق من HTTPS الموثوق وخدمة الطلاب الفعلية، لكنه لا يثبت ظهور إشعار الدخول على كل هاتف. قبل الامتحان اختبر Samsung وiPhone وهاتفًا أقدم: الاتصال بالشبكة، ظهور الإشعار أو فتح الرابط، الحل، فصل Wi-Fi وإعادته، والتسليم. تحقق من ساعة الهواتف، وإعدادات عزل العملاء وDHCP في نقطة الوصول، واحتفظ بالرابط وQR. لا تغيّر إعداد الشبكة أثناء قاعة مفتوحة.

وصّل كابل Omada قبل التهيئة. عند وجود أكثر من كابل Ethernet نشط، اترك كابل Omada وحده واستخدم Wi-Fi للإنترنت حتى لا يتغير المنفذ الخطأ. يمنع البرنامج فتح القاعات وبدءها أثناء التهيئة. إذا انتهت مهلة نافذة macOS دون تأكيد انتهاء العمل، قد يبقى المنع حتى عشر دقائق؛ إذا بقي قفل المثبّت أو لم تكتمل استعادة الإعداد، أعد تشغيل الماك وافحص الاتصال قبل فتح القاعات.

### اختصار شاشة الموبايل (0.4.20)

يظهر زر اختياري صغير فوق خانات تسجيل بيانات الطالب لإضافة «امتحانات مسار» إلى الشاشة الرئيسية. تظل خطوات الإضافة مخفية حتى يضغط الطالب عليه؛ من فتحت له الصفحة من إشعار الواي فاي يكمل تسجيله مباشرة دون إضافة اختصار أو تغيير المتصفح. الاختصار يفتح عنوان نفس الشبكة المحلية، ولا يحتاج تنزيل تطبيق من متجر أو اتصال إنترنت لتشغيل الامتحان. يجب أن يكون الماك والتطبيق ونقطة الوصول يعملون، وأن يكون الهاتف متصلًا بواي فاي الامتحان.

في الوضع العادي على HTTP، يعرض زر الاختصار إرشادات المتصفح؛ الصفحة لا تستطيع فرض نافذة تثبيت. Chrome وSamsung Internet يقدمان الإضافة إلى الشاشة الرئيسية من القائمة، وSafari من قائمة المشاركة. أسماء الأوامر تختلف حسب الإصدار. إذا أردت إضافة الاختصار والصفحة داخل نافذة تسجيل الدخول إلى الشبكة، افتح عنوان الامتحان في المتصفح العادي أولًا. عند إتاحة المتصفح نفسه نافذة تثبيت، يمكن طلبها بالضغط على الزر؛ إغلاق النافذة أو قبولها لا يثبت وحده اكتمال الإضافة.

أضف الاختصار وافتحه قبل تسجيل الدخول، ثم أكمل الامتحان في نفس النافذة. بعض الهواتف تفصل تخزين الاختصار عن المتصفح أو نافذة دخول الشبكة؛ الانتقال أثناء الحل قد يفقد الوصول إلى الجلسة أو المسودة في النافذة السابقة. لا تُعرض دعوة الإضافة أثناء المحاولة. من الإصدار 0.4.21، يبقى زر الاختصار ظاهرًا أثناء التسجيل حتى لو تعذر فحص التخزين أو كانت هناك مسودة تحتاج متابعة؛ عند الضغط يوضح السبب ويمنع النسخ والانتقال والتثبيت فقط، دون تعطيل تسجيل الطالب. لا تُخزّن واجهات الامتحان أو الإجابات في Service Worker؛ الحفظ والاستعادة يتبعان آلية الطالب الحالية.

### إصلاح انتظار الاتصال والتحديث (0.4.21)

أصبح النسخ الاحتياطي يستخدم اتصال قراءة مستقلًا بقاعدة البيانات، حتى لا يحجز اتصال دخول الطلاب وحفظ الإجابات أثناء إنشاء النسخة. لا يظهر ملف النسخة الاحتياطية للتحميل إلا بعد اكتماله. كانت صفحة الطالب في 0.4.21 تعيد محاولة تنزيل برنامج الصفحة عند فشل تنزيله، بحد أقصى ثلاث محاولات؛ استُبدلت هذه الآلية باستجابة واحدة في 0.4.22. ولا يوقف غياب واجهات تعريف المتصفح الاختيارية تحميل شاشة التسجيل؛ علامة المتصفح للمراقبة وليست مفتاح دخول.

أغلق القاعات وأنهِ الامتحانات قبل تحديث التطبيق. أغلق نسخة مسار المفتوحة، وثبّت النسخة الجديدة وافتحها من Applications؛ استبدال الملف على القرص لا يحدّث الخادم الذي يعمل بالفعل. بعد اتصال الهاتف بشبكة الامتحان، افتح `http://10.77.0.1/` وتأكد من ظهور `0.4.23` تحت اسم مسار. إذا تغير وضع الشبكة من HTTPS إلى المحلي، طبّق «تحديث تجهيز الماك» والقاعات مغلقة، ثم أعد اتصال الهواتف بالشبكة واستخدم الرابط المحلي قبل تسجيل الدخول. لا تتنقل بين الروابط أثناء محاولة الطالب.

اختبارات الخادم والهواتف المحاكية لا تثبت سلامة كابل أو نقطة وصول أو إعدادات هاتف بعينه. قبل الامتحان جرّب الدخول والحل وفصل Wi-Fi وإعادته والتسليم على الهواتف المستخدمة؛ لا تُمسح بيانات المتصفح عند وجود إجابات غير مستلمة.

### تحميل الصفحة وفحص توزيع العناوين (0.4.22)

تصل ملفات تشغيل الطالب وتنسيق الصفحة داخل استجابة HTML واحدة مضغوطة عندما يدعم المتصفح ذلك. لا يعود بدء التسجيل معتمدًا على تنزيل ملفات JavaScript وCSS منفصلة بعد الصفحة. تظل الخطوط والصور ملفات اختيارية منفصلة. يسمح CSP بتشغيل الحزمة وتنسيقها عبر بصماتهما المحددة فقط. لا يضيف هذا تخزينًا للامتحان في Service Worker، ولا يلغي حاجة حفظ الإجابات لاتصال بالماك.

تُغلق اتصالات HTTP وHTTPS الخاملة والطلبات ذات الجسم غير المكتمل بعد مهلة 30 ثانية، وتُحدّ مهلة إرسال ردود الطلاب. كتابة سجل البوابة تتم عبر طابور محدود؛ إذا امتلأ قد تُسقط بعض سجلات التشخيص حتى لا تتعطل طلبات الطلاب. تسجّل البوابة فئة خطأ الاتصال دون محتوى الإجابة، لتمييز انقطاع طلب الطالب عن رفض الخادم أو انتهاء المهلة. ويحرّر الخادم معاملة قاعدة البيانات إذا حدث خطأ برمجي مفاجئ أثناءها.

فحص الشبكة يميّز تشغيل العملية عن وجود منفذ DHCP فعلي، ويراجع واجهة الكابل وقناع الشبكة وإعداد الخدمة. عندما لا يوجد كابل نشط ويظل المنفذ المسجّل في إعداد DHCP ظاهرًا للنظام، يعرض الفحص هذا المنفذ بدل اختيار أول وصلة قديمة. إذا اختفى المنفذ أو وُجد كابل آخر نشط، يعرض السجل المنفذ المحدد وإعداد الخدمة للمقارنة. ترفض التهيئة تعارض منافذ DNS وDHCP قبل التغيير، ولا تعلن نجاح التجهيز قبل تحقق تشغيل الخدمة واستقبالها على منفذ DHCP. تظل هذه فحوصًا من الماك؛ يلزم هاتف متصل للتأكد من وصول عرض العنوان إليه.

بعد إنهاء الامتحانات وإغلاق القاعات: أغلق التطبيق القديم، واستبدله وافتح 0.4.22. وصّل الهاب وكابل نقطة الوصول، ثم استخدم «تحديث تجهيز الماك» لتطبيق تحديث خدمة البوابة، وراجع «فحص الاتصال». تحديث ملف التطبيق وحده لا يستبدل خدمة البوابة المثبتة في macOS. اختبر الدخول والحفظ والتسليم من هواتف القاعة قبل الامتحان التالي. لا تعِد تجهيز الشبكة أثناء محاولة طالب جارية.

عند تكرار المشكلة، نزّل سجل الشبكة بينما الهاب والكابل متصلان وسجّل وقت العطل. يوجد أيضًا `packaging/diagnose-mac-network.command` لتقرير قراءة فقط يحفظ في Downloads. أخطاء العنوان المفقود بعد فصل الهاب لا تثبت سبب عطل وقع قبله. السجل المرسل في هذه الواقعة أُخذ بعد الفصل؛ سبب تعثر توزيع العناوين أثناء الامتحان لم يُحسم منه.

أُعيد إنتاج تعطل بدء الصفحة في 0.4.21 بمنع طلبات الملفات الثانوية؛ اجتاز التعديل الدخول والحفظ وإعادة التحميل والتسليم في نفس الحالة. نجحت أيضًا اختبارات اتصالات TCP المتروكة واستعادة قاعدة البيانات بعد خطأ، واختبار 1000 طالب محاكى ببنك 100 سؤال وسحب 20 سؤالًا دون فشل. هذه النتائج لا تثبت قدرة الهاب أو نقطة الوصول أو إشعار الدخول التلقائي على جميع الهواتف الفعلية.

### التسجيل المباشر وتهيئة الهاب (0.4.23)

خانات الاسم والموبايل والكود موجودة في HTML الأول نفسه، ويُفعّل إرسالها عند تشغيل الحزمة المضمّنة دون انتظار فحص الجلسة والقاعة. تُحدّث حالة القاعة في الخلفية، مع بقاء الحقول المكتوبة ومؤشر الكتابة. يظل الخادم مسؤولًا عن قبول الدخول والتحقق من القاعة والمحاولة؛ ظهور النموذج لا يعني أن القاعة مفتوحة. عند وجود محاولة سابقة تستعاد بإجاباتها ومسودتها. لا يظهر اقتراح الاختصار قبل التحقق من عدم وجود جلسة طالب قائمة.

يفحص تجهيز الماك أن منفذ Ethernet المحدد ما زال موجودًا ورابط الكابل نشطًا بعد نافذة تصريح macOS وقبل تغيير الإعداد. بعد ضبط العنوان ينتظر ظهور `10.77.0.1/22` على واجهة النظام الفعلية قبل بدء DHCP، ويتحقق منه مجددًا قبل إتمام التهيئة. فشل تطبيق العنوان أو فقد الاتصال أثناء التهيئة يُفشل العملية ويشغّل استعادة الإعداد السابق؛ فشل الاستعادة يُعرض للمشرف. لا يعيد البرنامج ضبط الشبكة تلقائيًا عند فصل الهاب أثناء الامتحان.

«فحص الاتصال» يعرض اختلاف المنفذ الحالي عن المجهز، أو غياب العنوان الفعلي، أو تعذر قراءة الحالة. في الحالة الأخيرة لا يعرض الخدمات على أنها متوقفة أو جاهزة. لتطبيق الإصلاح: أنهِ الامتحانات وأغلق القاعات، وافتح 0.4.23، ووصّل الهاب والكابل، ثم اضغط «تهيئة الماك الآن» أو «تحديث تجهيز الماك». تثبيت نسخة التطبيق وحده لا يحدّث خدمات البوابة المثبتة في macOS.

### تقرير التشخيص أثناء الامتحان (0.4.24)

بعد تثبيت النسخة، أنهِ الامتحانات وأغلق القاعات، ووصّل الهاب والكابل واضغط «تحديث تجهيز الماك» لتحديث خدمة بوابة الدخول أيضًا. تسجيل التطبيق نفسه يبدأ عند فتحه؛ تحديث البوابة يتيح للخادم تمييز الأجهزة عند تحديد معدل استقبال تقارير المتصفحات.

يبدأ تسجيل حالة الشبكة عند فتح تطبيق الكمبيوتر، ويستمر عند الانتقال بين شاشاته. يفحص منفذ الهاب والعناوين الفعلية وخدمة DHCP وبوابة الدخول كل نحو 10 ثوانٍ، ويكتب التغيّرات ونبضة دورية كل نحو دقيقة. يسجل بداية التشغيل ونهايته والفجوات بين الفحوص، مع الوقت وتوقيت رتيب للمقارنة عند تغيّر ساعة الجهاز. نتيجة قديمة لا تُعرض على أنها تأكيد لسلامة الشبكة. التسجيل لا يغيّر إعداد الشبكة ولا يعيد تشغيل خدماتها.

من «الإعدادات والبيانات» ← «تهيئة الاتصال المباشر بالـOmada» ← «تشخيص الاتصال والأخطاء»:

- اضغط «سجّل وقت المشكلة» وقت حدوث التعليق لوضع علامة في السجل، دون قطع اتصال الطلاب.
- اضغط «تنزيل تقرير التشخيص» لحفظ ملف JSON محلي يجمع تاريخ فحص الشبكة، وحالتها الأخيرة، وسجل البوابة وDHCP، وتشخيص خادم الامتحان والمتصفحات المتاح. نزّله قبل إعادة التهيئة إن أمكن.
- اضغط «تحديث السجل» لمعرفة الأجزاء المتاحة. عند تعذر قراءة جزء أو الكتابة على القرص، يعرض التقرير حالة النقص؛ غياب سجل لا يثبت غياب المشكلة.

يسجل الخادم فئات الطلبات ومدتها ونتيجة الأخطاء، ويجمع الطلبات الناجحة في ملخصات. تحفظ صفحة الطالب قائمة محدودة بأحداث بدء الصفحة وانقطاع الاتصال ورجوعه وفشل الطلبات والأخطاء البرمجية، وتحاول إرسالها بعد استعادة الاتصال. تظل الإجابات في مسار حفظها المعتاد. إذا تعذر تشغيل شيفرة الصفحة أصلًا أو أغلق المتصفح قبل وصول الأحداث، قد لا يصل سجل من هذا الهاتف.

السجلات الجديدة تستخدم حقولًا محددة، دون أسماء الطلاب أو أرقامهم أو أكوادهم أو إجاباتهم أو نصوص الأخطاء أو كلمات السر. التقرير يتضمن عناوين الشبكة المحلية من سجل البوابة. تُحفظ السجلات محليًا بأحجام محدودة ويُستبدل الأقدم؛ لا يرفعها البرنامج تلقائيًا لأي موقع. احتفظ بالتقرير قريبًا من وقت المشكلة. لا ترسل ملف `room.log` أو مجلد البيانات كله بدلًا منه.

هذا الإصدار يحتفظ بنموذج التسجيل المباشر دون شاشة انتظار قبل البيانات. التشخيص يساعد في تحديد السبب، ولا يضمن فتح نافذة الدخول التلقائي على كل هاتف، ولا يسترجع تفاصيل الأعطال التي سبقت تثبيته.

إذا وصلت أول زيارة للبوابة بينما خادم الامتحان غير متاح، ترجع البوابة صفحة خطأ عربية خفيفة وزر إعادة المحاولة بدل جسم رد فارغ. تظل استجابة HTTP خطأ 502، ولا تتحول أخطاء حفظ الإجابات إلى صفحات HTML. هذا يعالج مسارًا محددًا للصفحة الفارغة، ولا يثبت حل شاشة `data:text/html` الخاصة بنظام هاتف بعينه. جميع وظائف الامتحان والشبكة المحلية المذكورة تعمل دون إنترنت.

## الراوتر أو هوت سبوت الكمبيوتر

البرنامج يحتاج شبكة محلية تصل الهواتف بالكمبيوتر؛ لا يشترط وجود راوتر بعينه. يمكن تجربة هوت سبوت الكمبيوتر بعدد قليل إذا كان نظام التشغيل وكارت الشبكة يسمحان بإنشاء الشبكة وتشغيلها بدون إنترنت. إعدادات مشاركة الإنترنت المعتادة في Windows وmacOS لا تضمن هذا الوضع، وحد الأجهزة المتصلة يختلف حسب الجهاز والنظام. لم نختبر الهوت سبوت على الجهاز الحالي، ولا نعتمد عليه لتجربة ١٠٠ طالب.

شغّل الشبكة قبل فتح البرنامج، ثم استخدم عنوان الكمبيوتر على شبكة الهوت سبوت. عنوان الهوت سبوت قد يختلف عن رابط شبكة الراوتر؛ يجب التأكد من عنوان الشبكة الصحيح قبل التجربة. فتح الامتحان تلقائيًا بمجرد الاتصال ليس من وظائف الهوت سبوت العادي أو هذه النسخة.

## الحفظ والوقت واستعادة الدخول

رسالة «تم الحفظ على الجهاز» تعني وصول آخر إجابات لجهاز الإدارة. أثناء انقطاع الاتصال يحتفظ المتصفح بمسودة ويحاول إرسالها عند عودته؛ عند انتهاء الوقت أو إنهاء المدرس تُعتمد آخر إجابات وصلت بالفعل للكمبيوتر. لا تعوّض المسودة المحلية انقطاعًا يستمر حتى بعد انتهاء الوقت.

استخدم متصفحًا واحدًا لكل طالب. إذا ضاع المتصفح أو تغير الموبايل، يضغط المشرف «استعادة الدخول»، ثم يدخل الطالب بنفس الكود ورقم الهاتف؛ تبقى إجاباته وموعد نهايته. إعادة تشغيل الكمبيوتر أو البرنامج لا توقف عداد الامتحان ولا تعيد الوقت. امنع نوم الكمبيوتر أثناء الجلسة.

الأسئلة تُقفل بعد فتح الانتظار. لتغيير امتحان مغلق، أنشئ نسخة جديدة منه؛ لها محاولات جديدة؛ يستخدم الطلاب أكوادهم نفسها.

## البيانات والنسخ الاحتياطية

النسخة المستقلة تحفظ البيانات خارج ملفات البرنامج، فلا تضيع عند استبدال حزمة التطبيق:

- macOS: `~/Library/Application Support/Massar Exam Room/exams.sqlite3`.
- Windows: `%LOCALAPPDATA%\Massar Exam Room\exams.sqlite3`.
- تشغيل `run.py` من المصدر: `data/exams.sqlite3` داخل مجلد المشروع، ما لم تحدد `--data-dir`.

ملف المفتاح `.env` موجود بجانب `exams.sqlite3` في مجلد البيانات نفسه، بصيغة `GEMINI_API_KEY=...`. يمكن إدخاله أو تغييره من «الإعدادات والبيانات» دون تعديل الملف يدويًا. النسخ الاحتياطية من اللوحة تحتوي SQLite فقط؛ احتفظ بالمفتاح منفصلًا إذا كنت تنقل البرنامج لجهاز آخر.

شاشة «الإعدادات والبيانات» تعرض المسار المستخدم بالفعل؛ زر «فتح مجلد البيانات» يفتحه على الكمبيوتر. سجل التشغيل `room.log` والنسخ في `backups/` بجانب قاعدة البيانات. لا تشارك هذا المجلد لأنه يحتوي بيانات الطلاب. نقل نسخة البرنامج إلى جهاز آخر لا ينقل امتحاناتك تلقائيًا.

تؤخذ نسخة SQLite متسقة عند التشغيل والإغلاق المعتاد وتغيير حالة الجلسة من اللوحة، وكل خمس دقائق أثناء التشغيل. إنشاء النسخة يدويًا أو تنزيلها متاح أيضًا. لا يوجد حذف تلقائي؛ انقل نسخًا لقرص آخر وراقب المساحة. فحص السلامة يفحص بنية SQLite، ولا يثبت اكتمال إجابات لم تصل عبر الشبكة.

للاسترجاع اليدوي:

1. نزّل النسخة وافتح مجلد البيانات من البرنامج ثم أغلق البرنامج بالكامل.
2. أعد تسمية مجلد البيانات الحالي للاحتفاظ به، وأنشئ مجلدًا فارغًا بنفس الاسم والمكان.
3. ضع النسخة المطلوبة فيه باسم `exams.sqlite3` فقط، بدون نسخ ملفات WAL أو ملفات أخرى من المجلد القديم.
4. افتح البرنامج وراجع الامتحانات والنتائج قبل استقبال الطلاب. الوقت المنقضي أثناء التوقف يظل محسوبًا.

للتجربة من المصدر في مجلد منفصل: `python3 run.py --data-dir /path/to/recovered-data`؛ استبدل المسار بمجلدك. النسخ الاحتياطية المتسقة هي وسيلة النقل، وليس نسخ الملف المفتوح أثناء التشغيل. الاسترجاع ليس زرًا آليًا في هذه النسخة.

لوحة الإدارة متاحة من الكمبيوتر فقط على المنفذ 8766. الطلاب يستخدمون المنفذ 8765. اتصال الهواتف HTTP محلي غير مشفر؛ النسخة للتجربة على شبكة خاصة موثوقة، ولا ينبغي نشرها على الإنترنت. إذا تغير عنوان الكمبيوتر عند الانتقال لراوتر آخر، أعد تشغيل البرنامج وشارك الرابط الجديد.

## التحقق للمطور

من داخل مجلد التطبيق:

```sh
go test ./...
python3 tests/load_go.py
python3 tests/load_go.py --clients 20 --chaos --poll-rounds 10
python3 tests/load_go.py --clients 10000 --chaos --poll-rounds 10 --workers 256
```

اختبارات Go تستخدم قاعدة مؤقتة، وتغطي دورة الامتحان وحفظ الإجابات والتقارير وحماية واجهات الإدارة. اختبار الضغط ينشئ ١٠٠ جلسة HTTP على الكمبيوتر نفسه. اختبار `--chaos` يُدخل انقطاعًا وتأخيرًا وإعادة طلبات الحفظ والتسليم. عند طلب أكثر من ١٠٠٠ جلسة، تبني أداة القياس خادمًا بعلامة اختبار خاصة ترفع حد الجلسة إلى ١٠٬٠٠٠؛ التطبيق المثبت يحتفظ بحد ١٠٠٠ طالب في الامتحان الواحد. يُحدد `--workers` عدد الطلبات التي تُرسل في اللحظة الواحدة. تُحذف بيانات الاختبار المؤقتة بعد انتهائه؛ لا يغير امتحانات المستخدم ولا يقيس تغطية الواي فاي أو قدرة الراوتر على استقبال آلاف الأجهزة لاسلكيًا.

تفاصيل التحقق الفعلي في `VERIFICATION.md`.

### شيتات وتقارير الطلاب (0.3.0)

- قائمة «واتساب السنتر» تربط Meta Cloud API وتعرض القوالب الرسمية. الإرسال يحتاج قالبًا معتمدًا برأس Document ومزامنة خلال آخر 10 دقائق، ثم معاينة المستلمين وتأكيد الإرسال. التفاصيل في قسم 0.4.4 أدناه.
- للتشغيل من المصدر، مرّر `--pdf-helper` مع مسار مولّد التقرير المجمّع. عند البناء يستعمل `build_desktop.py` المتطلبات المثبتة في `requirements-desktop.txt` ويضم المولّد للتطبيق.

### إدارة الامتحان أثناء التشغيل (0.3.1)

### الغياب واستكمال المحاولة (0.3.3)

### كروت حالات الطلاب (0.4.1)

- فلاتر الحضور والتسليم والتصحيح والإلغاء أصبحت كروت؛ كل كارت يعرض عدد الطلاب، والضغط عليه يصفّي الجدول. الكارت المختار يظهر بعلامة صح ولون واضح، مع اسم الحالة المعروضة أسفله. البحث يحدّث الأعداد والجدول معًا.
- عند تفعيل مراقبة الشاشة أو وجود بيانات شاشة محفوظة تظهر كروت إضافية: ملء الشاشة، خارج ملء الشاشة، مساحة عرض أقل، علامة متصفح مختلفة، ملء الشاشة غير مدعوم، وبدون بيانات شاشة. تعتمد على آخر تقرير محفوظ وتشمل المحاولات غير المسلّمة وغير الملغاة.
- الحالات قد تتداخل: الطالب الموقوف قد يظهر أيضًا في خارج ملء الشاشة، والمسلم في كارت التسليم والتصحيح. انخفاض المساحة وتغير العلامة يعتمدان على الإشارة الحالية، وليس التنبيه القديم بعد عودة الوضع الطبيعي.
- الكروت تتكيف مع عرض مساحة الإدارة: ستة أعمدة عند اتساعها، أربعة في العرض المعتاد، وعمودان في الشاشة الصغيرة، وعمود واحد للمساحة الأضيق.

### ترتيب الطلاب (0.4.2)

- بجانب البحث، اختر أحدث دخول أولًا (الافتراضي)، أقدم دخول، أحدث ظهور، أحدث تسليم، الاسم، الكود رقميًا، أعلى أو أقل درجة بعد التصحيح، أو الأقرب لانتهاء الوقت. الترتيب يعمل مع كارت الحالة والبحث في القاعة والنتائج، ويستمر أثناء تحديث البيانات.
- وقت أول دخول يظهر تحت الاسم بتوقيت القاهرة؛ العودة بنفس الكود لا تغير وقت الدخول الأول. أحدث ظهور يعتمد على آخر تحديث اتصال محفوظ.
- ترتيب الدرجات يقدم المحاولات المسلّمة المكتملة التصحيح وغير الملغاة؛ الدرجة صفر نتيجة صحيحة للترتيب. ترتيب انتهاء الوقت يقدم المحاولات غير المسلّمة وغير الملغاة. المحاولات التي لا ينطبق عليها معيار الترتيب تأتي في النهاية.

### المشاكل أولًا (0.4.3)

- «المشاكل أولًا» مفعّل افتراضيًا بجانب ترتيب الطلاب. يقدم الطلاب الذين يحتاجون متابعة، مع الاحتفاظ بالترتيب المختار داخل مجموعة المشاكل وباقي الطلاب. يمكن تعطيله للوصول للترتيب وحده، ويعمل مع كارت الحالة والبحث. العدد بجانبه يخص الطلاب الظاهرين.
- تشمل المتابعة المحاولة غير المسلّمة في قاعة مفتوحة: إيقاف مؤقت، خروج من الصفحة، غياب تحديث الاتصال 15 ثانية، انتهاء الوقت دون تسليم، أو تنبيه شاشة حالي عند تفعيل مراقبتها. يميز الصف بلون هادئ ويعرض السبب. عند زوال الحالة يرجع الطالب لمكانه في الترتيب العادي.
- المسلّم، الملغي، والمقالي المنتظر للتصحيح لا يعتبرون مشكلة حضور. المتصفح غير الداعم لملء الشاشة وغياب بيانات شاشة وحدهما لا يرفعان الطالب؛ التنبيهات السابقة بعد زوالها أو تعطيل المراقبة لا ترفعه.

### واتساب السنتر وإرسال التقارير (0.4.9)

- احفظ Phone Number ID وWhatsApp Business Account ID المختلفين والتوكن في «واتساب السنتر»، وتتحدث القوالب تلقائيًا عند فتح شاشة واتساب أو نافذة الإرسال، وكل خمس دقائق أثناء فتح الشاشة. عند الحاجة إلى تحديثها قبل المعاينة أو الإرسال ينفذ البرنامج التحديث تلقائيًا؛ فشل التحديث يمنع إرسال بيانات قديمة ويعرض سبب التعذر. البرنامج يتحقق أن رقم الإرسال ضمن الحساب المختار. الأسرار في ملف `whatsapp-cloud.json` خاص بجانب قاعدة البيانات، خارج SQLite والنسخ الاحتياطية؛ لا تدخل في المثبّت. على جهاز جديد يلزم ربط الحساب مرة أخرى.
- القوالب المعتمدة من نوع Utility أو Marketing ذات رأس Document تُستخدم لإرفاق PDF. متغيرات النص العددية المتصلة تُربط باسم الطالب، الكود، الدرجة، المجموع، النتيجة أو اسم الامتحان، مع دعم النص الثابت. القوالب ذات المتغيرات المسماة أو الأزرار الديناميكية تظهر مع سبب عدم دعمها.
- زر إرسال التقارير في نتائج القاعة أو الشيتات يعرض المستلمين والأرقام واسم الملف وبيانات الرسالة قبل التأكيد. المحاولات الملغاة أو غير المسلّمة أو غير مكتملة التصحيح لا تدخل الإرسال. يستخدم رقم الطالب المصري المسجل، ويحوله إلى الصيغة الدولية. كل طالب يستقبل ملفه فقط.
- الإرسال في دفعات حتى خمسة تقارير معًا، ثم انتظار خمس ثوانٍ بعد اكتمال الدفعة قبل التالية. الإرسال يعمل في الخلفية داخل البرنامج، وتظهر حالته أعلى لوحة الإدارة. يمكن تغيير الصفحة والعمل في امتحان آخر وإضافة تقاريره للدور؛ تكتمل عملية الإرسال الحالية أولًا ثم تبدأ التالية. زر الإيقاف يمنع الدفعات التالية بعد انتهاء الحالية. تُحفظ العمليات والتقدم في SQLite؛ عند إغلاق البرنامج تتوقف العمليات وتحتاج مراجعة السجل وإعادة معاينة الباقي بعد فتحه، ولا تُعاد الرسائل المقبولة أو غير المؤكدة تلقائيًا. يلزم إنترنت على الماك حتى رفع التقارير وقبول الطلبات، مع إبقاء البرنامج مفتوحًا. قبول Meta يُحفظ مع معرف الرسالة؛ «مقبولة» لا تعني وصلت أو قُرئت. التقرير الذي تغيّر بعد المعاينة يتطلب معاينة جديدة. الطلب المقبول أو غير المؤكد لا يُكرر تلقائيًا؛ الطلب الذي فشل قبل الإرسال أو رفضته Meta له إعادة محاولة بتأكيد منفصل.
- التوكن وApp Secret لا يظهران بعد الحفظ، وتغيير التوكن أو الحساب يمسح القوالب القديمة وApp Secret السابق إلا إذا أُدخل معه سر جديد. بيانات الويب هوك تعرض Verify Token فقط؛ ربط رابط المنصة واستقبال حالات الوصول مستقل عن سجل القبول المحلي في هذه النسخة.
- ويب هوك الامتحانات المستقل هو `https://api.massar-academy.net/api/exam-room/whatsapp/webhook`، بإعدادات خاصة بالحساب الجديد. تفاصيل النشر والحفظ في `docs/production/exam-whatsapp-webhook.md` في جذر المشروع. سجل البرنامج الحالي يعرض قبول الإرسال فقط.
- يحتاج جهاز الإدارة إنترنت للمزامنة والإرسال. يظل الامتحان وحفظ الإجابات وتقارير PDF محليًا. الإصدار الحالي بُني واختُبر على macOS Apple Silicon؛ مصدر Windows موجود، لكن مثبّت Windows لم يُبنَ أو يُختبر لهذا الإصدار.
