# مسار · امتحانات السنتر — نسخة تجربة محلية

تطبيق مستقل بهوية مسار. الكمبيوتر يستضيف الامتحان ويحفظ البيانات، والطلاب يفتحونه من متصفح الموبايل على نفس الشبكة. التشغيل والامتحان لا يحتاجان إنترنت، ولا يستخدم التطبيق حسابات أو قواعد بيانات منصة مسار.

البرنامج له باك إند محلي مكتوب بـGo يحفظ البيانات في SQLite على نفس الكمبيوتر. واجهة الإدارة داخل البرنامج مكتوبة بـReact وتُبنى كملفات ثابتة مضمّنة في خادم Go؛ صفحة الطالب خفيفة بـHTML وCSS وJavaScript. حزمة سطح المكتب تستخدم Python وpywebview فقط لفتح نافذة البرنامج وتشغيل خادم Go. لا يوجد خادم سحابي للامتحان؛ اتصال الإنترنت مطلوب فقط عند طلب تصحيح Gemini. ملفات Python داخل `room/` محفوظة كمرجع للنسخة السابقة؛ التشغيل الحالي يستخدم خادم Go فقط.

## التشغيل كبرنامج مستقل

مثبّت macOS للنسخة الجديدة هو `dist/Massar-Exam-Room-macOS-arm64-Installer.pkg`. افتحه واتبع خطوات التثبيت؛ سيضع `Massar Exam Room.app` في مجلد Applications. لا تحتاج تثبيت Python أو Go على الجهاز الذي سيستخدم البرنامج. توجد أيضًا نسخة ZIP محمولة في `dist/Massar-Exam-Room-macOS-arm64-Go.zip`. نافذة الإدارة وخادم الطلاب يعملان معًا، وإغلاق البرنامج يوقف اتصال الطلاب بعد تنبيه تأكيد. اتركه مفتوحًا طوال الامتحان. إذا كانت نسخة أقدم مفتوحة، أنهِ الجلسة وأغلقها أولًا ثم افتح الحزمة الجديدة؛ تظل قاعدة البيانات في مجلدها الثابت.

النسخة مبنية على جهاز Apple Silicon ومجرّبة على macOS 26.3. لم نختبرها على Intel أو إصدارات macOS أقدم. التطبيق داخل الحزمة موقّع محليًا، لكن ملف `.pkg` غير موقّع بشهادة Developer ID Installer ولم يخضع لتوثيق Apple notarization. قد يمنع macOS فتحه مباشرة؛ افتحه من قائمة زر الماوس الأيمن ← «فتح»، أو اسمح به من إعدادات الخصوصية والأمان بعد محاولة الفتح. للتوزيع العام السلس يلزم توقيع Apple وتوثيق الحزمة.

في Windows توجد أداة بناء `Build-Windows.bat`، **ولا يوجد مثبّت Windows مبني أو مجرّب في هذه البيئة**. تُشغّل الأداة على Windows مع Python 3.10+ وGo 1.27.1 أو أحدث وNode.js/npm وInno Setup 6 واتصال إنترنت لتنزيل حزم البناء. الناتج `dist/Massar-Exam-Room-Windows-Setup.exe`، وهو مثبّت يضع التطبيق في Program Files ويضيف اختصارًا. التشغيل الناتج يحتاج Microsoft Edge WebView2 Runtime. البناء على كل نظام مستقل، حسب [توثيق PyInstaller](https://www.pyinstaller.org/en/stable/). اعتمد نسخة Windows بعد اختبارها على الجهاز المستهدف.

لبناء نسخة macOS من المصدر يلزم Go وNode.js/npm وPython وحزم سطح المكتب:

```sh
python3 -m venv .build-env
.build-env/bin/python -m pip install -r requirements-desktop.txt
.build-env/bin/python build_desktop.py
```

## التشغيل من المصدر في المتصفح

هذا البديل يحتاج Python 3.10+ وGo 1.27.1 أو أحدث لبناء وتشغيل الخادم: `Start-Massar.command` على macOS أو `Start-Massar.bat` على Windows. أبقِ نافذة التشغيل مفتوحة. أو شغّل من مجلد التطبيق:

```sh
python3 run.py
```

على Windows استخدم `py -3 run.py`. يُبنى خادم Go محليًا عند تشغيل المصدر. لوحة الإدارة `http://127.0.0.1:8766`؛ الطلاب على منفذ 8765. لا تشغّل البرنامج ونسخة المصدر معًا على نفس المنافذ. البيانات المفتوحة في عملية أخرى محمية بقفل نظام التشغيل؛ عند رسالة التعارض أغلق النسخة الأخرى وأعد المحاولة.

## أول تجربة

1. وصّل الكمبيوتر والهواتف بنفس الراوتر، ويفضل كابل شبكة للكمبيوتر. يمكن فصل الإنترنت عن الراوتر مع بقاء الشبكة المحلية تعمل.
2. اسمح لاتصالات برنامج مسار الواردة (أو خادم Go عند التشغيل من المصدر) على الشبكة الخاصة إذا طلب جدار الحماية ذلك. لا تفتح المنفذ على الإنترنت. يجب أن يسمح إعداد الشبكة للهواتف بالوصول إلى الكمبيوتر؛ شبكة الضيوف المعزولة قد تمنع ذلك.
3. اضغط «ابدأ بامتحان تجريبي»: أربعة أسئلة جاهزة. أو أنشئ أسئلتك من «إنشاء امتحان».
4. افتح قاعة الانتظار؛ لا تحتاج توليد أو توزيع أكواد للامتحان. افتح على الموبايل **رابط الطلاب الظاهر في اللوحة** أو امسح QR. عنوان `127.0.0.1` يخص الكمبيوتر نفسه ولا يصلح على هاتف الطالب.
5. الطالب يكتب اسمه ورقمه وكوده الحالي في السنتر، وينتظر. البيانات تُقبل كما كتبها الطالب بدون مراجعة كشف مسبق؛ الكود ليس كلمة سر أو كود شراء. يُمنع تكرار نفس الكود في نفس الامتحان، ويُسمح باستخدامه في امتحانات أخرى. اضغط «ابدأ الامتحان للجميع» لبدء الوقت وظهور الأسئلة تلقائيًا خلال دورة التحديث، عادة نحو ثلاث ثوانٍ.
6. افتح «الإعدادات والبيانات» وأدخل مفتاح Gemini API في قسم «إعدادات التصحيح» مرة واحدة. بعد إنهاء الامتحان، افتح «التصحيح والنتائج» واضغط «تصحيح المقالي للجميع» وانتظر اكتمال العداد. راجع الإجابات التي تحتاج تدخلًا، ويمكنك تعديل أي درجة يدويًا. عند اكتمال التصحيح افتح «تقرير التصحيح / PDF»، ثم اختر الحفظ كـPDF من نافذة الطباعة.

ابدأ بعدد قليل من الهواتف ثم زوّد العدد. اختبار ١٠٠ جلسة على الكمبيوتر لا يثبت قدرة الراوتر على خدمة ١٠٠ موبايل فعلي.

## الموجود في النسخة

- أسئلة اختيارات ومقالي مكتوب، درجات وإجابات نموذجية، ترتيب عشوائي واختيار عدد من بنك الأسئلة.
- عند اختيار عينة من البنك، يجب أن تكون درجات الأسئلة متساوية حتى يتساوى المجموع بين الطلاب.
- نهاية موحدة للجميع، أو مدة كاملة للطالب المتأخر؛ الطلاب الموجودون في الانتظار يبدأ وقتهم عند بدء المدرس. يمكن منع الدخول المتأخر.
- تسجيل بكود الطالب الحالي، حضور، حفظ تلقائي للإجابات، استعادة الدخول، تسليم يدوي أو عند انتهاء الوقت.
- سؤال واحد ظاهر في كل خطوة مع السابق والتالي وأرقام للتنقل. الإجابات والخطوة الحالية تبقيان بعد إعادة تحميل الصفحة، والتسليم متاح من الخطوة الأخيرة.
- لا تُرسل الإجابات النموذجية أو الدرجات إلى واجهة الطالب؛ بعد التسليم يرى تأكيد الاستلام فقط.
- تصحيح MCQ تلقائي، وتصحيح مقالي جماعي عبر Gemini بعد انتهاء الامتحان، مع إمكانية المراجعة والتعديل اليدوي، وتقارير قابلة للطباعة، وتصدير CSV.
- مكتبة امتحانات قابلة للبحث والتصفية، وفلاتر حضور وتسليم وتصحيح، وتنبيه قبل مغادرة تعديل غير محفوظ.
- شاشة «الإعدادات والبيانات» تعرض المسار الفعلي والحجم والمساحة المتاحة والعدادات، وتفتح المجلد وتفحص بنية SQLite وتُنشئ وتُنزل النسخ.
- قاعدة SQLite مستقلة ونسخ احتياطية محلية. خادم Go يقرأ قاعدة النسخة الحالية ويحافظ على المحاولات والإجابات، ويرقّي مخطط SQLite رقم 1 إلى رقم 2 تلقائيًا بعد إنشاء نسخة احتياطية.

التصحيح الجماعي يحتاج إنترنت على جهاز الإدارة فقط. يرسل نص السؤال والإجابة النموذجية وإجابة الطالب إلى Gemini، بدون اسم الطالب أو هاتفه؛ يقيّم كل إجابة صح أو غلط بلا درجات جزئية. الإجابة الملتبسة تبقى للمراجعة اليدوية. يُحفظ المفتاح نصيًا في ملف `.env` داخل مجلد بيانات البرنامج، وليس داخل SQLite أو حزمة التطبيق أو ملفات النسخ الاحتياطية؛ الملف مخصص لحساب مستخدم الكمبيوتر فقط ولا يُنشر في المصدر. لا تشارك ملف `.env` لأنه يحتوي المفتاح. إذا كان المفتاح في Keychain من نسخة قديمة فقط، أدخله مجددًا من شاشة الإعدادات ليُحفظ في `.env`. قد تنطبق حدود الاستخدام وتكاليف حساب Google؛ توقف الشبكة أو انتهاء الحصة يترك ما صُحح محفوظًا، ويمكن إعادة تشغيل الباقي. راجع أحكام Gemini قبل اعتماد النتائج النهائية.

**غير منفّذ في هذه النسخة:** إرسال Meta WhatsApp، توليد وإرسال ملفات PDF دفعة واحدة، وبوابة الراوتر التي تفتح الصفحة تلقائيًا. QR يفتح رابط الامتحان بعد الاتصال بالشبكة، ولا يربط الهاتف بالواي فاي تلقائيًا. النظام لا يمنع استخدام بيانات الموبايل أو تطبيقات أخرى.

### بوابة Omada EAP620 HD المحلية (إعداد اختياري)

الـEAP620 HD في وضعه المستقل يوفّر `Wireless > Portal > No Authentication`، لكن خانة `The Promotional URL` في إصدار البرنامج الثابت المجرب لا تقبل المنفذ `:8765`. على الماك يمكن بناء وتثبيت `install-macos-portal.sh` من هذا المجلد؛ يفتح خدمة الطلاب فقط على منفذ HTTP الافتراضي 80 ويحيلها إلى `127.0.0.1:8765`. لا يفتح لوحة الإدارة على 8766. سيطلب `sudo` كلمة مرور macOS من صاحب الجهاز في Terminal. للإزالة استخدم `uninstall-macos-portal.sh`.

يمكن الاستغناء عن الراوتر نهائيًا في شبكة الامتحان: `Mac Ethernet → EAP620 HD → هواتف الطلاب`. إذا كان الأكسس بوينت يتغذّى من محوّل 12V/1.5A مستقل، وصّل كابل الشبكة مباشرةً. في هذا التوصيل يصبح الماك مسؤولًا عن إعطاء عناوين IP للطلاب عبر خدمة DHCP محلية، مع عنوان ثابت لنفسه وللأكسس بوينت. لا يكفي توصيل الكابل وحده؛ الـEAP في وضع Access Point لا يؤدي وظيفة DHCP التي يؤديها الراوتر عادةً.

في نسخة الماك 0.2.6، افتح «الإعدادات والبيانات» ← «تهيئة الاتصال المباشر بالـOmada» واضغط «تهيئة الماك الآن». يطلب macOS كلمة سر الجهاز في نافذته المعتادة؛ التطبيق لا يستقبلها. يجهّز عنوان الماك `10.77.0.1/22`، ويحجز `10.77.0.2` للأكسس بوينت، ويوزّع العناوين `10.77.0.20` حتى `10.77.3.250`، ويثبّت وصلة منفذ 80 المذكورة أعلاه. يكتشف منفذ Ethernet الموجود على الجهاز، بما فيه محوّلات USB، ولا يحتاج إنترنت يوم الامتحان. يتضمن المثبّت خدمة توزيع العناوين ولا يحتاج تثبيت Homebrew على ماك الامتحان. إذا توقفت الخدمة، يعرض البرنامج سبب التوقف من سجلها المحلي. شيفرة المصدر ورخصة dnsmasq 2.93 داخل التطبيق في `Contents/Resources/third-party/`. يظل `install-macos-direct-network.sh` بديلًا من المصدر، وللإزالة واستعادة إعداد Ethernet السابق القائم على DHCP استخدم `uninstall-macos-direct-network.sh`. هذا الإعداد لم يُشغّل أو يُختبر بعد على الأجهزة الفعلية؛ اختبره بهواتف حقيقية وابدأ بعدد صغير قبل الاعتماد عليه مع 500 طالب.

بعد تشغيل DHCP وربط الأجهزة، اختبر `http://10.77.0.1/` من هاتف على شبكة الامتحان أولًا. النسخة 0.2.6 توجّه فحوص الاتصال عبر HTTP إلى صفحة الطلاب المحلية، كي يستطيع الهاتف إظهار نافذة الدخول. لا تفعّل بوابة الـOmada الداخلية إذا أردت صفحة الامتحان مباشرة؛ بوابة No Authentication تعرض صفحة موافقة وزر دخول قبل التحويل. ظهور نافذة الدخول تلقائيًا يعتمد على نظام الهاتف ولا يمكن ضمانه لكل الأجهزة، لذا احتفظ برمز QR أو رابط الامتحان كبديل.

على Windows يمكن تشغيل خادم الطلاب مباشرة على المنفذ 80 (`--port 80`) بعد التأكد أنه غير مستخدم، وإضافة سماح وارد لشبكة الامتحان الخاصة فقط. يحتاج ذلك بناء حزمة Windows واختبارها على الجهاز المستهدف؛ لم يتم التحقق من Windows هنا. احفظ عنوان الكمبيوتر ثابتًا في الراوتر واستخدم `http://<عنوان الكمبيوتر>/` عنوان تحويل البوابة.

## الراوتر أو هوت سبوت الكمبيوتر

البرنامج يحتاج شبكة محلية تصل الهواتف بالكمبيوتر؛ لا يشترط وجود راوتر بعينه. يمكن تجربة هوت سبوت الكمبيوتر بعدد قليل إذا كان نظام التشغيل وكارت الشبكة يسمحان بإنشاء الشبكة وتشغيلها بدون إنترنت. إعدادات مشاركة الإنترنت المعتادة في Windows وmacOS لا تضمن هذا الوضع، وحد الأجهزة المتصلة يختلف حسب الجهاز والنظام. لم نختبر الهوت سبوت على الجهاز الحالي، ولا نعتمد عليه لتجربة ١٠٠ طالب.

شغّل الشبكة قبل فتح البرنامج، ثم استخدم عنوان الكمبيوتر على شبكة الهوت سبوت. عنوان الهوت سبوت قد يختلف عن رابط شبكة الراوتر؛ يجب التأكد من عنوان الشبكة الصحيح قبل التجربة. فتح الامتحان تلقائيًا بمجرد الاتصال ليس من وظائف الهوت سبوت العادي أو هذه النسخة.

## الحفظ والوقت واستعادة الدخول

رسالة «تم الحفظ على الجهاز» تعني وصول آخر إجابات لجهاز الإدارة. أثناء انقطاع الاتصال يحتفظ المتصفح بمسودة ويحاول إرسالها عند عودته؛ عند انتهاء الوقت أو إنهاء المدرس تُعتمد آخر إجابات وصلت بالفعل للكمبيوتر. لا تعوّض المسودة المحلية انقطاعًا يستمر حتى بعد انتهاء الوقت.

استخدم متصفحًا واحدًا لكل طالب. إذا ضاع المتصفح أو تغير الموبايل، يضغط المشرف «استعادة الدخول»، ثم يدخل الطالب بنفس الكود ورقم الهاتف؛ تبقى إجاباته وموعد نهايته. إعادة تشغيل الكمبيوتر أو البرنامج لا توقف عداد الامتحان ولا تعيد الوقت. امنع نوم الكمبيوتر أثناء الجلسة.

الأسئلة تُقفل بعد فتح الانتظار. لتغيير امتحان مغلق، أنشئ نسخة جديدة منه؛ لها محاولات جديدة؛ يستخدم الطلاب أكوادهم نفسها.

## البيانات والنسخ الاحتياطية

النسخة المستقلة تحفظ البيانات خارج ملفات البرنامج، فلا تضيع عند استبدال حزمة التطبيق:

- macOS: `~/Library/Application Support/Massar Exam Room/exams.sqlite3`.
- Windows: `%LOCALAPPDATA%\Massar Exam Room\exams.sqlite3`.
- تشغيل `run.py` من المصدر: `data/exams.sqlite3` داخل مجلد المشروع، ما لم تحدد `--data-dir`.

ملف المفتاح `.env` موجود بجانب `exams.sqlite3` في مجلد البيانات نفسه، بصيغة `GEMINI_API_KEY=...`. يمكن إدخاله أو تغييره من «الإعدادات والبيانات» دون تعديل الملف يدويًا. النسخ الاحتياطية من اللوحة تحتوي SQLite فقط؛ احتفظ بالمفتاح منفصلًا إذا كنت تنقل البرنامج لجهاز آخر.

شاشة «الإعدادات والبيانات» تعرض المسار المستخدم بالفعل؛ زر «فتح مجلد البيانات» يفتحه على الكمبيوتر. سجل التشغيل `room.log` والنسخ في `backups/` بجانب قاعدة البيانات. لا تشارك هذا المجلد لأنه يحتوي بيانات الطلاب. نقل نسخة البرنامج إلى جهاز آخر لا ينقل امتحاناتك تلقائيًا.

تؤخذ نسخة SQLite متسقة عند التشغيل والإغلاق المعتاد وتغيير حالة الجلسة من اللوحة، وكل خمس دقائق أثناء التشغيل. إنشاء النسخة يدويًا أو تنزيلها متاح أيضًا. لا يوجد حذف تلقائي؛ انقل نسخًا لقرص آخر وراقب المساحة. فحص السلامة يفحص بنية SQLite، ولا يثبت اكتمال إجابات لم تصل عبر الشبكة.

للاسترجاع اليدوي:

1. نزّل النسخة وافتح مجلد البيانات من البرنامج ثم أغلق البرنامج بالكامل.
2. أعد تسمية مجلد البيانات الحالي للاحتفاظ به، وأنشئ مجلدًا فارغًا بنفس الاسم والمكان.
3. ضع النسخة المطلوبة فيه باسم `exams.sqlite3` فقط، بدون نسخ ملفات WAL أو ملفات أخرى من المجلد القديم.
4. افتح البرنامج وراجع الامتحانات والنتائج قبل استقبال الطلاب. الوقت المنقضي أثناء التوقف يظل محسوبًا.

للتجربة من المصدر في مجلد منفصل: `python3 run.py --data-dir /path/to/recovered-data`؛ استبدل المسار بمجلدك. النسخ الاحتياطية المتسقة هي وسيلة النقل، وليس نسخ الملف المفتوح أثناء التشغيل. الاسترجاع ليس زرًا آليًا في هذه النسخة.

لوحة الإدارة متاحة من الكمبيوتر فقط على المنفذ 8766. الطلاب يستخدمون المنفذ 8765. اتصال الهواتف HTTP محلي غير مشفر؛ النسخة للتجربة على شبكة خاصة موثوقة، ولا ينبغي نشرها على الإنترنت. إذا تغير عنوان الكمبيوتر عند الانتقال لراوتر آخر، أعد تشغيل البرنامج وشارك الرابط الجديد.

## التحقق للمطور

من داخل مجلد التطبيق:

```sh
go test ./...
python3 tests/load_go.py
python3 tests/load_go.py --clients 20 --chaos --poll-rounds 10
python3 tests/load_go.py --clients 10000 --chaos --poll-rounds 10 --workers 256
```

اختبارات Go تستخدم قاعدة مؤقتة، وتغطي دورة الامتحان وحفظ الإجابات والتقارير وحماية واجهات الإدارة. اختبار الضغط ينشئ ١٠٠ جلسة HTTP على الكمبيوتر نفسه. اختبار `--chaos` يُدخل انقطاعًا وتأخيرًا وإعادة طلبات الحفظ والتسليم. عند طلب أكثر من ١٠٠٠ جلسة، تبني أداة القياس خادمًا بعلامة اختبار خاصة ترفع حد الجلسة إلى ١٠٬٠٠٠؛ التطبيق المثبت يحتفظ بحد ١٠٠٠ طالب في الامتحان الواحد. يُحدد `--workers` عدد الطلبات التي تُرسل في اللحظة الواحدة. تُحذف بيانات الاختبار المؤقتة بعد انتهائه؛ لا يغير امتحانات المستخدم ولا يقيس تغطية الواي فاي أو قدرة الراوتر على استقبال آلاف الأجهزة لاسلكيًا.

تفاصيل التحقق الفعلي في `VERIFICATION.md`.

- البيانات الصغيرة تنتظر تأكيد الحفظ وتُرسل بمحاولة keepalive عند إخفاء الصفحة؛ المسودات المحلية تظل مهمة عند انقطاع الاتصال. إعادة الدخول من متصفح آخر تسترجع ما وصل فعليًا للسيرفر.
- لا يمكن HTTPS وحده إجبار متصفح مغلق على الفتح أو فصل Wi-Fi الموبايل. فصل العميل من نقطة الوصول يحتاج ربط إدارة Omada، وهو غير مضاف هنا.

### واتساب السنتر وإرسال التقارير (0.4.4)

- احفظ Phone Number ID وWhatsApp Business Account ID المختلفين والتوكن في «واتساب السنتر»، ثم زامن القوالب. البرنامج يتحقق أن رقم الإرسال ضمن الحساب المختار. الأسرار في ملف `whatsapp-cloud.json` خاص بجانب قاعدة البيانات، خارج SQLite والنسخ الاحتياطية؛ لا تدخل في المثبّت. على جهاز جديد يلزم ربط الحساب مرة أخرى.
- القوالب المعتمدة من نوع Utility أو Marketing ذات رأس Document تُستخدم لإرفاق PDF. متغيرات النص العددية المتصلة تُربط باسم الطالب، الكود، الدرجة، المجموع، النتيجة أو اسم الامتحان، مع دعم النص الثابت. القوالب ذات المتغيرات المسماة أو الأزرار الديناميكية تظهر مع سبب عدم دعمها.
- زر إرسال التقارير في نتائج القاعة أو الشيتات يعرض المستلمين والأرقام واسم الملف وبيانات الرسالة قبل التأكيد. المحاولات الملغاة أو غير المسلّمة أو غير مكتملة التصحيح لا تدخل الإرسال. يستخدم رقم الطالب المصري المسجل، ويحوله إلى الصيغة الدولية. كل طالب يستقبل ملفه فقط.
- الإرسال متتابع مع زر إيقاف بعد الطلب الحالي. قبول Meta يُحفظ مع معرف الرسالة؛ «مقبولة» لا تعني وصلت أو قُرئت. التقرير الذي تغيّر بعد المعاينة يتطلب معاينة جديدة. الطلب المقبول أو غير المؤكد لا يُكرر تلقائيًا؛ الطلب الذي فشل قبل الإرسال أو رفضته Meta له إعادة محاولة بتأكيد منفصل.
- التوكن وApp Secret لا يظهران بعد الحفظ، وتغيير التوكن أو الحساب يمسح القوالب القديمة وApp Secret السابق إلا إذا أُدخل معه سر جديد. بيانات الويب هوك تعرض Verify Token فقط؛ ربط رابط المنصة واستقبال حالات الوصول مستقل عن سجل القبول المحلي في هذه النسخة.
- ويب هوك الامتحانات المستقل هو `https://api.massar-academy.net/api/exam-room/whatsapp/webhook`، بإعدادات خاصة بالحساب الجديد. تفاصيل النشر والحفظ في `docs/production/exam-whatsapp-webhook.md` في جذر المشروع. سجل البرنامج الحالي يعرض قبول الإرسال فقط.
- يحتاج جهاز الإدارة إنترنت للمزامنة والإرسال. يظل الامتحان وحفظ الإجابات وتقارير PDF محليًا. الإصدار الحالي بُني واختُبر على macOS Apple Silicon؛ مصدر Windows موجود، لكن مثبّت Windows لم يُبنَ أو يُختبر لهذا الإصدار.
