# Data Model: Authentication, Sessions, and Permission Safety

## User

Existing entity: `backend/src/NaderGorge.Domain/Entities/User.cs`

New/confirmed fields:

- `IsActive: bool` existing. Must be checked during access-token validation and refresh.
- `PasswordResetVersion: int` existing. Must be included in token claims and checked during validation.
- `SecurityStampVersion: int` new. Increment whenever broad session invalidation is required: account disable/reactivation where sessions should reset, role/permission changes, and security-sensitive admin actions.

Validation rules:

- Access token is valid only when `User.Id` exists, `IsActive == true`, token `passwordResetVersion` equals current `PasswordResetVersion`, and token `securityStampVersion` equals current `SecurityStampVersion`.
- Tokens missing required version claims are stale and rejected.

State transitions:

- Active user disabled → `IsActive=false`, `SecurityStampVersion++`, active refresh tokens revoked.
- Password reset complete → `PasswordResetVersion++`, `SecurityStampVersion++` optional if implementation uses both, active refresh tokens revoked.
- Role/permission assignment changed → `SecurityStampVersion++`, active refresh tokens revoked.

## RefreshToken

Existing entity: `backend/src/NaderGorge.Domain/Entities/RefreshToken.cs`

Confirmed fields:

- `UserId: Guid`
- `Token: string`
- `ExpiresAt: DateTime`
- `IsRevoked: bool`
- `DeviceFingerprint: string?`

Validation rules:

- Refresh is valid only when token exists, not revoked before atomic consume, not expired, linked user exists and active, and linked device is active when a fingerprint is present and a matching device record exists.
- A consumed refresh token is revoked before a replacement token is created.
- Rejected refresh attempts must not create a replacement token.

State transitions:

- Active → consumed/revoked during refresh.
- Active → revoked during logout, password reset, account disable, role change, or device revocation.

## Device

Existing entity: `backend/src/NaderGorge.Domain/Entities/Device.cs`

Confirmed fields:

- `UserId: Guid`
- `DeviceFingerprint: string`
- `IsActive: bool`

Validation rules:

- Device revocation prevents refresh for refresh tokens carrying that device fingerprint.
- Removing or deactivating a device revokes refresh tokens for the same user and fingerprint.

## Admin Route Permission Rule

Frontend data contract in `frontend/src/packages/admin/route-permissions.ts`

Fields:

- `pattern: string` route pattern such as `/admin/users/:id`
- `permission?: string`
- `adminOnly?: boolean`
- `allowRoles?: string[]` only where a role-level exception is intentional

Validation rules:

- `/admin` root is allowed for admin-surface users.
- Known route pattern with `permission` requires matching user permission unless user is full Admin/Supervisor.
- Known `adminOnly` route requires full Admin/Supervisor.
- Unknown `/admin/*` route denies for staff-like non-admin users.

## Parent Report Token

Existing signed URL token generated by `ParentController`.

Fields:

- `StudentId: Guid`
- `Purpose: "parent-report"`
- `Exp: long` Unix timestamp

Validation rules:

- Token must have valid HMAC signature, matching student id, exact purpose, and future expiration.
- Issued lifetime must be shortened from the current seven-day default to the Phase 1 configured lifetime.
- Invalid or expired token returns safe denial without report data.
