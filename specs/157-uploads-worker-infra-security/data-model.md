# Data Model: Uploads, Assets, Worker, and Infrastructure Security

No mandatory database schema change is planned. The model below describes existing and logical entities that implementation must preserve or harden.

## UploadedAsset

Represents a stored file from admin content, sales template, recharge screenshot, question image, teacher photo, live support attachment, subtitle, or mind-map flow.

**Fields**

- `originalFileName`: user-supplied display name, sanitized before persistence or response.
- `normalizedFileName`: generated server-side filename; must not contain path separators, control characters, executable/browser-interpretable extension, or user-controlled prefix.
- `declaredContentType`: client-provided MIME; informational only.
- `detectedContentType`: MIME inferred from magic bytes or trusted decoder.
- `extension`: normalized lower-case extension selected from detected safe type.
- `storagePath`: relative path under approved public or private root.
- `classification`: `public-safe-image`, `protected-resource`, `private-attachment`, `worker-generated-public-artifact`, or `rejected`.
- `sizeBytes`: original upload size after request limit.
- `sha256`: required for private/live-support attachments where already supported.

**Validation Rules**

- Extension, declared type, and detected bytes must be compatible with the allowed category.
- SVG, HTML, XML, script-capable content, and unknown binaries are rejected for browser-inline public paths.
- ZIP/doc formats may be accepted only as attachment/protected-resource, never public inline.
- Stored filename is generated by the server and never uses raw user input except optional sanitized display name metadata.

## ProtectedResourceDownload

Represents a signed or authenticated download of lesson resources.

**Fields**

- `resourceId`: existing LessonResource id.
- `token`: existing signed token.
- `expiresAt`: token expiration.
- `resolvedStoragePath`: safe relative path under approved root.
- `contentDisposition`: always attachment for untrusted/protected resources.
- `contentType`: `application/octet-stream` unless a safe explicit type is required.

**State Transitions**

- `requested` → `validated` → `resolved` → `downloaded`.
- `requested` → `denied` for missing/invalid/expired token.
- `resolved` → `not-found` when metadata points to missing disk file.

## LiveSupportAttachment

Existing database entity for support attachments.

**Fields Already Present**

- `StoragePath`
- `OriginalFileName`
- `ContentType`
- `SizeBytes`
- `Sha256`
- `UploadedByIdentity`
- `IsBlocked`

**Hardening Rules**

- `OriginalFileName` is display-only and sanitized.
- `ContentType` must be detected/normalized, not copied blindly from client.
- Unsafe browser-interpretable content is rejected or served only as attachment with safe type.
- Download requires participant authorization already enforced by `LiveSupportService`.

## WorkerAdminRequest

Logical entity for worker admin access attempts.

**Fields**

- `route`: `/ui`, `/api/status/:id`, `/internal/live-support/preview`, retry/cancel endpoints.
- `method`: HTTP method.
- `remoteAddressHash`: redacted/hardened identity for rate limit/audit.
- `authorized`: boolean.
- `reason`: `missing-token`, `invalid-token`, `disabled`, `rate-limited`, `allowed`.
- `timestamp`: UTC.

**Rules**

- Production default is disabled unless explicitly enabled.
- Unauthorized and rate-limited attempts must be logged through redacted logger.

## QueueJobIngestion

Logical representation of a Redis stream message converted to BullMQ.

**Fields**

- `messageStreamId`
- `jobType`
- `sourceJobId`
- `targetQueue`
- `targetJobName`
- `targetJobId`
- `payload`
- `existingState`
- `action`: `enqueue`, `skip-existing`, `ack-invalid`, `retry-existing`, `dead-letter` if added later.

**Rules**

- `targetJobId` is the idempotency key.
- Ordinary ingestion must not remove existing BullMQ jobs.
- Ordinary ingestion must not clear cancellation markers.
- Explicit admin retry may clear cancellation only for failed jobs.
- Invalid/unknown/unparseable messages are acknowledged and deleted after redacted logging.

## StreamRecoveryCursor

Logical Redis stream recovery state.

**Fields**

- `stream`: `job-stream`
- `group`: `worker-group`
- `consumer`
- `minIdleMs`
- `startId`
- `claimedCount`

**Rules**

- Recovery must claim stale pending messages from dead consumers before or alongside normal reads.
- Claimed messages use the same idempotent ingestion path as new messages.
- A message is acknowledged only after the ingestion decision is durably made.

## ExternalOperationFailure

Represents sanitized worker failure classification.

**Fields**

- `operation`: `callback`, `download`, `ai`, `conversion`, `telegram`, `cobalt`, `yt-dlp`, `redis`, `database`.
- `category`: `timeout`, `network`, `authentication`, `permission`, `quota-exhausted`, `validation`, `not-found`, `provider`, `conversion`, `cancelled`, `implementation`.
- `retryable`: boolean.
- `remediation`: operator-safe short message.
- `status`: optional numeric status.

**Rules**

- No raw URL, token, prompt, response body, or stderr is exposed in user/admin-facing messages.
- Logs may include redacted metadata only.
